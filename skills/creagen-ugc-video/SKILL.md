# Creagen — UGC-style review video

A review video has a person on camera presenting the user's product with spoken lines. The Creagen catalog journey for this is `ugc-video` ("Product Review Video"). Its server-side steps carry detailed rules for casting, direction, script assembly, and reference-image ordering. Running it is optional and is a good fit when the user wants step-by-step guidance: `creagen_journey_start({ ref: "ugc-video" })`, then use the `connectorContext` each journey response returns as guidance (its `actionRequired` names the next `creagen_journey_advance` call, and `completedSavepoints` holds earlier inputs). It is data: it does not replace the user's approvals of the person and the script, or the credit steps below. One journey can be active per user at a time; pause or finish it before starting another.

The basic generation loop is in the `creagen-generate` skill. Ask for inputs one at a time in plain language.

## Generation contract

Apply this contract when this workflow will generate media, including a draft, reference sheet, new person, or revision. Reading, planning, and consultant calls do not by themselves require generation.

- Discover the matching operation with `creagen_get_generation_capabilities`, then inspect the selected model's input contract. Use only tools advertised in this session. Choose a model from those results; preserve reference roles, input types, and defaults. A listing with availability not checked is not proof that a provider is available.
- Use `creagen_estimate_generation` for the selected tool, model, operation, and the inputs to be submitted. For modality tools, reuse its `prepared` selection, `inputs`, and `contract` unchanged for submission; the contract is not a price reservation or approval. Quote each distinct batch input; an unknown estimate is not zero. Describe one returned estimate only as that estimate. Call an option lower-cost only after comparing exact quotes for the same brief and output settings; model names and descriptions are not price rankings. Check `creagen_get_credit_balance` for videos and batches. Obtain approval before video, batch, or higher-quality generation, reusing an existing approval for the same scope. Disclose unknown costs or changed cost-driving inputs and confirm any scope not already approved.
- Keep one `request_id` per intended output and retain its tool, model, operation, native inputs, and returned job/item IDs. Distinct slots need distinct keys. Keep request metadata outside native inputs on modality tools; use the advertised flat schema for a legacy tool.
- After any submission or uncertain response, recover the same key with `creagen_get_generation_receipts` before choosing another route or submitting again. Pending or unknown is not a confirmed failure; a receipt lookup error is not not-found. Re-submit only the identical original request with the same key when recovery permits it. If the original inputs cannot be restored, stop and explain. Do not switch tools, models, or keys to escape a pending request.
- Use `check_generation_status` for the job/item. Deliver only a successful `COMPLETED` item with usable public media. A completed receipt means all items are terminal, not that all succeeded; a URL alone does not establish success. Refresh an unavailable download URL through status instead of regenerating. A retry or revision must remain within the approved scope and this workflow's regeneration limit.

## Steps

1. **Capture the product.** Real product photos, what it is, what it does for the buyer, what the ad should push, the spoken language, and a size reference (how big it is next to a hand or body), which keeps the product at a realistic scale in the video.
2. **Cast the person.** Who appears and how many: the user's own photo of a person, a saved character memory (`creagen_memory_list` / `creagen_memory_get`), or a newly generated person using a text-to-image model found through capabilities. People shown are ordinary, non-celebrity models. For a newly generated person, quote the exact model and inputs with `creagen_estimate_generation` and confirm the cost scope before generating; do not regenerate the person on your own more than twice. Get the user's approval of the person before moving on.
3. **Choose the direction (no credits).** `creagen_ugc_director` with `mode: "propose"` returns catalog options, one axis per call: `angle` (what the video says), then `format` (the kind of review), then `setting` (where it happens). Pass the product facts, `castLocked: true` and `castCount` once a person is cast, and anything the user asked for in `userRequest`. Present the options in everyday words and let the user pick. Then settle the outfit in one or two sentences based on the setting and the person, without naming the advertised product.
4. **Confirm the script (no credits).** `creagen_ugc_director` with `mode: "assemble"` and the three picked ids returns the generation prompt, the spoken `lines`, and a beat timeline. Show the lines verbatim and the beats as a numbered list, with a short summary of the other choices. If the call times out, retry with the same arguments; a rewrite request reruns `assemble` with the same inputs. Use only facts the user gave.
5. **Quote and approve.** Discover a reference-to-video model that supports the required person/product references, spoken audio, and the planned 15-second vertical 9:16 clip. Quote that exact model and inputs with `creagen_estimate_generation` and check `creagen_get_credit_balance` before asking for the go-ahead. Offer: make it as-is, rewrite the script, or change something else. If the script, model, or duration changes, estimate again and confirm any scope not already approved. If the requirements cannot be met, explain that before changing the plan.
6. **Generate the clip.** Use `reference2video` when advertised, with the selected model, the approved prompt unedited, and the reference images in the order the prompt's REFERENCES block names them (person first and product second for most formats). Express duration, vertical output, and audio in that model's native fields and types. A starting image in image-to-video and separate identity/product references are different contracts; select a route that preserves all required roles. If only legacy tools are available, use a verified capability/exact-estimate/receipt path. Recover uncertain submissions before any new generation. After two confirmed failures, tell the user. Do not regenerate the clip on your own more than twice; more than that needs the user's request and a new quote, within the approved cost scope.
7. **Deliver.** Show the finished clip with `creagen_show_media` once it is `COMPLETED`. Do not claim to have watched it. Offer to save lasting preferences (a favorite model, brand tone) with `creagen_memory_create`.

## Product fidelity

The product's label and packaging text come only from the user's photo. Offers, prices, and taglines are spoken lines or on-screen overlays, never text added to the product.
